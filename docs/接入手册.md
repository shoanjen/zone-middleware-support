# zone-middleware 二方包接入手册

> 适用版本：`1.0.0-SNAPSHOT` · GroupId：`com.zone.middleware` · 更新日期：2026-11-21
>
> 上游接入支持两种方式：**按需引入**（只取所需模块）与**套件引入**（`zone-middleware-suite` 单坐标全量引入），见第 3 节。

## 1. 适用对象与环境要求

本手册面向使用 Zone 二方库的上游 Spring Boot 应用开发者。

| 项 | 要求 |
|---|---|
| JDK | **21+**（不向下兼容） |
| Spring Boot | **3.x**（本库基于 3.5.6 BOM 编译，兼容 3.1+；自动装配通过 `META-INF/spring/…AutoConfiguration.imports` 注册，jakarta 命名空间） |
| JSON | 统一 **fastjson2**（随依赖传递）；**禁止引入 jackson** |
| Lombok | 仅本库编译期使用（`optional`，不传递给上游） |
| 服务器资源 | 本库为纯二方库，**不监听端口、不启动服务**；MySQL/Redis 由上游直连共享实例，以独立 database / db index 隔离 |

## 2. 模块总览与选型

| 模块 | 能力 | 自动传递 |
|---|---|---|
| `zone-middleware-common` | `ZoneResult` 统一返回体、错误码体系 + 业务异常、`BaseRequest`、常量接口、工具类 | —（纯工具模块，无 Spring 强依赖） |
| `zone-middleware-log` | `ZoneLog` 统一日志门面、`ZoneTraceContext` 双标识上下文 | common |
| `zone-middleware-redis` | `ZoneRedisTemplate`（String/Hash/List/Set/ZSet + 批量）、Lettuce 连接池、LOCAL/CLOUD 预设 | log、common |
| `zone-middleware-database` | 数据源（HikariCP/Druid 切换）、MyBatis-Plus、Flyway；不含 JPA | log、common |
| `zone-middleware-http` | `ZoneHttpTemplate`（JDK HttpClient）、鉴权拦截、并发上限、重试、熔断 | log、common |
| `zone-middleware-security` | 接口签名鉴权（MD5 签名 + `@ZoneSignCheck` 注解 + 防重放）与登录令牌（不透明令牌 + Redis） | log、redis、common |
| `zone-middleware-suite` | **全量套件聚合坐标**（packaging=pom）：一次引入上述全部模块 | 全部模块及其传递依赖 |

> 传递规则：除 common 外，**任何能力模块都自动传递 log 与 common**，无需重复引入。

## 3. 接入方式

二方包支持两种接入方式，按上游应用的需要二选一。

### 3.1 方式一：按需引入（推荐）

只引入当前用到的能力模块，依赖体积最小。场景对照：

| 上游需求 | 引入坐标 | 自动带上的能力 |
|---|---|---|
| 只要统一返回体 / 错误码 / 工具类 | `zone-middleware-common` | 无 |
| 只要统一日志 | `zone-middleware-log` | common |
| 需要 Redis 操作 | `zone-middleware-redis` | log、common |
| 需要 MySQL / MyBatis-Plus / Flyway | `zone-middleware-database` | log、common |
| 需要 HTTP 客户端 | `zone-middleware-http` | log、common |
| 需要接口签名鉴权 / 用户登录令牌 | `zone-middleware-security` | log、redis、common |

示例：应用只需要 Redis 与统一日志（log 会被 redis 传递，无需显式声明）：

```xml
<properties>
    <zone-middleware.version>1.0.0-SNAPSHOT</zone-middleware.version>
</properties>

<dependency>
    <groupId>com.zone.middleware</groupId>
    <artifactId>zone-middleware-redis</artifactId>
    <version>${zone-middleware.version}</version>
</dependency>
```

### 3.2 方式二：套件引入（全量，单坐标）

新应用一步到位、或团队希望统一技术栈时，引入套件聚合坐标即可传递全部模块（common + log + redis + database + http + security 及其全部传递依赖）：

```xml
<dependency>
    <groupId>com.zone.middleware</groupId>
    <artifactId>zone-middleware-suite</artifactId>
    <version>1.0.0-SNAPSHOT</version>
    <type>pom</type>
</dependency>
```

> ⚠️ **必须声明 `<type>pom</type>`**：`zone-middleware-suite` 是 `packaging=pom` 的聚合坐标，不产出 jar；缺省时 Maven 按默认 `jar` 类型解析，依赖解析阶段即报 `Could not find artifact com.zone.middleware:zone-middleware-suite:jar:1.0.0-SNAPSHOT`。

等价的手动全量引入（不想用套件坐标时，可逐个声明六个模块，效果相同；无需 `<type>pom</type>`）：

```xml
<properties>
    <zone-middleware.version>1.0.0-SNAPSHOT</zone-middleware.version>
</properties>

<dependency>
    <groupId>com.zone.middleware</groupId>
    <artifactId>zone-middleware-common</artifactId>
    <version>${zone-middleware.version}</version>
</dependency>
<dependency>
    <groupId>com.zone.middleware</groupId>
    <artifactId>zone-middleware-log</artifactId>
    <version>${zone-middleware.version}</version>
</dependency>
<dependency>
    <groupId>com.zone.middleware</groupId>
    <artifactId>zone-middleware-redis</artifactId>
    <version>${zone-middleware.version}</version>
</dependency>
<dependency>
    <groupId>com.zone.middleware</groupId>
    <artifactId>zone-middleware-database</artifactId>
    <version>${zone-middleware.version}</version>
</dependency>
<dependency>
    <groupId>com.zone.middleware</groupId>
    <artifactId>zone-middleware-http</artifactId>
    <version>${zone-middleware.version}</version>
</dependency>
<dependency>
    <groupId>com.zone.middleware</groupId>
    <artifactId>zone-middleware-security</artifactId>
    <version>${zone-middleware.version}</version>
</dependency>
```

> ⚠️ **接入提示**：`com.zone.middleware:zone-middleware` 是构建聚合父 POM，**不是接入坐标**——依赖它只会传递 `zone-middleware-common` 与 `spring-boot-starter`，不会带入五个能力模块（log / redis / database / http / security）；套件入口请用 `zone-middleware-suite`。

**套件引入后的配置义务**：所有模块均为 Spring Boot 自动装配（`AutoConfiguration.imports` + `EnvironmentPostProcessor`），**引入即生效，无需 `@EnableXXX` 或额外配置类**。但有两项**必配**（缺失均启动失败）：

| 必配项 | 触发条件 | 处理 |
|---|---|---|
| `spring.datasource.url` | 引入 database 模块（套件必含） | 配置数据库连接 URL（第 7 节） |
| `zone.middleware.security.sign.secret` | 引入 security 模块且未关闭签名校验（`sign.enabled` 默认 `true`） | 配置双端约定签名密钥（第 9 节）；纯令牌/不需要签名时显式设 `zone.middleware.security.sign.enabled=false` |

其余能力（log / redis / http）无必配项，套件引入后请按第 6–9 节补齐所用能力的配置；确实用不到某能力时建议改用按需引入，避免携带无关依赖。

## 4. zone-middleware-common

无任何配置项，引入即用。

### 4.1 统一返回体 ZoneResult

```java
ZoneResult.ok();                                  // success=true, code=SUCCESS, data=null
ZoneResult.ok(data);                              // 携带数据
ZoneResult.fail(BusinessError.DATA_NOT_FOUND);    // success=false, code=BIZ-4004
ZoneResult.fail(SystemError.CONFIG_ERROR, "缺少 redis 配置"); // 自定义消息覆盖默认描述
```

字段：`success` / `code` / `message` / `data` / `timestamp`（毫秒，工厂方法自动打点）。

### 4.2 错误码与业务异常

- `SystemError`（SYS- 前缀，基础设施层面）、`BusinessError`（BIZ- 前缀，业务层面）；
- 业务失败直接抛异常，由上游全局异常处理器统一转 `ZoneResult`：

```java
throw new ZoneBusinessException(BusinessError.PARAM_INVALID, "订单号不能为空");
```

完整码表见第 10 节。

### 4.3 基础请求 BaseRequest

请求 DTO 继承后统一携带：`reqId` / `platform` / `ip` / `deviceId` / `os` / `version` / `timestamp` / `sign`。

```java
public class OrderQueryRequest extends BaseRequest {
    private String orderNo;
}

// platform / os 为字符串透传（未知值不强转），需要枚举规约时：
Platform platform = Platform.of(request.getPlatform()); // "web" → WEB；未知值 → null
OsType os = OsType.of(request.getOs());                 // "harmony" → HARMONY
```

### 4.4 工具类

| 类 | 用途 |
|---|---|
| `ZoneIpUtils` | 从请求头/连接信息解析客户端真实 IP |
| `ZoneBrowserUtils` | 浏览器 UA 解析（返回 `ZoneBrowserInfo`；基于 UserAgentUtils，已单点隔离可替换） |
| `ZoneRandomUtils` | 分段随机字符串生成 |

### 4.5 顶层常量接口 ZoneConstants

上层按领域派生，继承即获得内置协议头常量：

```java
public interface OrderConstants extends ZoneConstants {
    String ORDER_STATUS_PAID = "PAID";
}
OrderConstants.HEADER_ACCESS_TOKEN;  // "Zone-Access-Token"
OrderConstants.HEADER_TRACE_ID;      // "Zone-Trace-Id"（出站链路透传头）
```

## 5. zone-middleware-log

### 5.1 配置项

| 键 | 默认 | 说明 |
|---|---|---|
| `zone.middleware.log.app-name` | `spring.application.name` 回退 `unknown` | 日志应用名段 |
| `zone.middleware.log.env` | `spring.profiles.active` 首段回退 `unknown` | 环境标识段 |
| `zone.middleware.log.format` | `TEXT` | 行格式 `TEXT`/`JSON`，非法值**启动失败** |
| `zone.middleware.log.level` | `INFO` | 最低输出级别 |
| `zone.middleware.log.include-trace-id` | `true` | 是否输出 traceId 段 |
| `zone.middleware.log.include-app-name` | `true` | 是否输出应用名段 |

`application.yml` 示例（JSON 采集模式，全部键 + 默认值）：

```yaml
zone:
  middleware:
    log:
      app-name: order-service          # 缺省回退 spring.application.name
      env: dev                          # 缺省回退 spring.profiles.active 首段
      format: JSON                      # TEXT（默认）/ JSON
      level: INFO                       # DEBUG / INFO / WARN / ERROR
      include-trace-id: true
      include-app-name: true
```

properties 风格见第 11 节全量参考。设置在环境准备阶段即生效（`EnvironmentPostProcessor` 早期应用），**先于一切 Bean 初始化日志**。

### 5.2 ZoneLog 用法（静态门面，无 AOP）

```java
// 基础：{} 占位符 + 变参，告别 + 拼接
ZoneLog.info("OrderService", "createOrder", "订单{}创建成功,金额{}", orderId, amount);

// 业务数据三形态：JSON 字符串透传 / 对象自动 JSON / 多变量按序填充
ZoneLog.info("OrderService", "createOrder", "用户数据: {}", "{\"orderId\":123}");
ZoneLog.info("OrderService", "createOrder", "订单{}创建成功", Map.of("orderId", 123));

// 异常堆栈：末位未消费的 Throwable 自动输出；或显式异常重载（异常可放首位）
ZoneLog.error("OrderService", "save", "订单{}保存失败", orderId, exception);

// 显式级别
ZoneLog.log(ZoneLogLevel.WARN, "OrderService", "createOrder", "库存不足,订单{}", orderId);
```

占位符渲染：字符串原样、数值/布尔/字符按字面值、其他对象 fastjson2 JSON、null→`null`；多余参数忽略。

### 5.3 链路上下文 ZoneTraceContext

`traceId`（跨服务串联）+ `reqId`（单请求标识）双标识，基于线程级 MDC，**由调用方显式传入**（本库不生成）：

```java
ZoneTraceContext.bind("t-20261121-001", "r-0001");  // 入口绑定
try {
    // 同线程内 ZoneLog 输出自动携带
} finally {
    ZoneTraceContext.clear();                        // 出口清理，防线程复用串号
}
```

- 不跨线程池自动传播：异步场景请在提交任务前显式复制 MDC；
- 跨服务串联用 traceId，出站请求头取 `ZoneConstants.HEADER_TRACE_ID`；reqId 不定义协议头。

### 5.4 行格式

- **TEXT**（默认）：`应用名 | 环境 | traceId | reqId | 类名.方法名 | 消息`，开关关闭或值缺席的段直接跳过（时间/级别由底层 pattern 输出）；
- **JSON**：每行一个完整 JSON 对象（字段 time/level/appName/env/traceId/reqId/class/method/message/exception），采集端零解析规则；建议 logback pattern 只保留消息体与换行：

```xml
<pattern>%m%n</pattern>
```

## 6. zone-middleware-redis

### 6.1 配置项

**连接配置全部使用 Spring Boot 官方键**（`spring.data.redis.*`，由官方 `RedisAutoConfiguration` 装配连接工厂），本模块只保留一个行为键：

| 键 | 默认 | 说明 |
|---|---|---|
| `zone.middleware.redis.mode` | `LOCAL` | `LOCAL`/`CLOUD` 部署模式预设；预设经官方键承载，显式配置总是优先 |
| `spring.data.redis.host` / `port` | `127.0.0.1` / `6379` | 连接地址（官方键） |
| `spring.data.redis.password` | — | 无密码留空（官方键） |
| `spring.data.redis.database` | `0` | db index，与其他应用隔离（官方键） |
| `spring.data.redis.ssl.enabled` | `false` | 云端按需开启 TLS（Boot 3.1+ 为对象键 `ssl.enabled`，非布尔 `ssl`） |
| `spring.data.redis.connect-timeout` | LOCAL 预设 2s / CLOUD 预设 10s | 连接超时（官方键） |
| `spring.data.redis.timeout` | LOCAL 预设 3s / CLOUD 预设 10s | 命令超时（官方键） |
| `spring.data.redis.lettuce.pool.max-active` / `max-idle` / `min-idle` / `max-wait` | 预设 8 / 8 / 0 / 2s | Lettuce 连接池（官方键；需 commons-pool2，本模块已随依赖引入） |
| —（无官方键） | LOCAL 关 / CLOUD 开 | TCP 保活：无官方配置键，本模块按 `mode` 经 Lettuce ClientOptions 定制器应用 |

`application.yml` 示例（本地共享实例 + 独立 db 隔离；未列出的超时/池参数项自动取 mode 预设）：

```yaml
spring:
  data:
    redis:
      host: 127.0.0.1
      port: 6379
      password: ""             # 无密码留空
      database: 1              # 与其他应用用 db index 隔离
      ssl: false

zone:
  middleware:
    redis:
      mode: LOCAL              # LOCAL / CLOUD：超时/保活预设开关
```

> ℹ️ 连接工厂由 Spring 官方装配；本模块在其之上只做模板装配、模式预设与 TCP 保活（TCP 保活按 `mode` 自动应用；Boot 3.1–3.3 且开启 TLS 的场景 keepAlive 不生效，Boot 3.4+ 无此限制）。上游自定义 `LettuceConnectionFactory` / `StringRedisTemplate` / `ZoneRedisTemplate` Bean 可整体接管（装配均 `@ConditionalOnMissingBean`）。

### 6.2 用法

```java
@Autowired ZoneRedisTemplate redis;

// String
redis.set("user:1", user, Duration.ofMinutes(5));
User u = redis.get("user:1", User.class);
redis.delete("user:1");

// 批量
List<User> users = redis.mGet(List.of("user:1", "user:2"), User.class);
redis.deleteKeys(List.of("user:1", "user:2"));

// Hash / List / Set / ZSet
redis.hSet("user:1:ext", "level", 5);
Integer level = redis.hGet("user:1:ext", "level", Integer.class);
redis.lPush("queue:mail", task);
redis.sAdd("tags:1", "vip", "new");
redis.zAdd("rank:score", player, 98.5);
```

值统一以 fastjson2 JSON 字符串存储（redis-cli 可直接阅读），读取按指定类型还原；键/字段不存在时返回 null 或空集合，不抛异常。上游自定义 `LettuceConnectionFactory` / `StringRedisTemplate` / `ZoneRedisTemplate` Bean 可整体接管（装配均 `@ConditionalOnMissingBean`）。

## 7. zone-middleware-database

### 7.1 前置条件

**MySQL 驱动由上游自行引入**（本库不锁定版本）：

```xml
<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
</dependency>
```

### 7.2 配置项

**连接、池参数与迁移控制全部使用 Spring Boot 官方键**（`spring.datasource.*` / `spring.flyway.*`），本模块只保留行为键：

| 键 | 默认 | 说明 |
|---|---|---|
| `zone.middleware.db.mode` | `LOCAL` | LOCAL：预设开启 Hikari 泄漏检测(10s)便于开发；CLOUD：预设获取超时 15s、保活 120s、关泄漏检测；预设经官方键承载，显式配置总是优先 |
| `spring.datasource.url` / `username` / `password` / `driver-class-name` | —（**url 必填**） | 连接信息（官方键）；缺 url **启动失败**，抛 `SYS-1001 CONFIG_ERROR` |
| `spring.datasource.type` | HikariCP（缺省） | 连接池切换（官方键）：填 `com.alibaba.druid.pool.DruidDataSource` 切 Druid；不可解析取值启动失败 |
| `spring.datasource.hikari.maximum-pool-size` 等 | 预设/官方默认 | Hikari 池参数（官方键，显式配置覆盖预设） |
| `spring.datasource.druid.initial-size` / `min-idle` / `max-active` / `max-wait` / `keep-alive` | 预设 2 / 2 / 8 / LOCAL 5s·CLOUD 15s / CLOUD true | Druid 池参数（官方键） |
| `spring.datasource.druid.filters` | — | Druid filter 别名列表（逗号分隔，如 `stat,wall,slf4j`）；本库会预校验别名，未注册别名**启动失败**（Druid 原生行为是静默跳过，为防能力静默丢失故改为快速失败） |
| `zone.middleware.db.mybatis.pagination-enabled` | `true` | 分页插件（方言自动识别）——本库行为键 |
| `zone.middleware.db.mybatis.mapper-package` | — | 配置后自动扫描注册 Mapper；不配则上游自行 `@MapperScan`——本库行为键 |
| `spring.flyway.enabled` | `true` | 迁移开关（官方键） |
| `spring.flyway.locations` | 预设 `classpath:db/migration` | 迁移脚本路径（官方键） |
| `spring.flyway.baseline-on-migrate` | 预设 `false` | 对已有数据的库开启基线化（官方键） |

`application.yml` 示例（Hikari + MyBatis-Plus 分页 + Flyway，最小必配集为 url/username/password）：

```yaml
spring:
  datasource:
    url: jdbc:mysql://127.0.0.1:3306/app_db?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
    username: app
    password: ${DB_PASSWORD}          # 建议经环境变量注入，不落明文
    driver-class-name: com.mysql.cj.jdbc.Driver
    # type: com.alibaba.druid.pool.DruidDataSource   # 切 Druid（缺省 HikariCP）
    # druid:
    #   filters: stat,wall           # Druid 可选配 filter（监控统计/防火墙/日志）

  flyway:
    enabled: true
    locations: classpath:db/migration
    baseline-on-migrate: false      # 对已有数据的库改为 true

zone:
  middleware:
    db:
      mode: LOCAL                   # LOCAL / CLOUD：池参数预设开关
      mybatis:
        mapper-package: com.example.app.mapper   # 配置后自动扫描注册 Mapper
        pagination-enabled: true
```

### 7.3 用法

```java
// Mapper 继承 BaseMapper 即可；分页开箱即用
@Mapper
public interface ZoneUserMapper extends BaseMapper<ZoneUser> {}

Page<ZoneUser> page = zoneUserMapper.selectPage(new Page<>(1, 10), null);
```

- **事务**：Spring Boot 基于 zone 装配的数据源自动生效，`@Transactional` 正常使用；
- **Druid SQL 监控/防火墙**：配 `spring.datasource.druid.filters` 即可（如 `stat,wall,slf4j`），本库负责装配与别名校验；
- **Druid 监控页（stat-view-servlet）**：属应用层决策（暴露生产数据面），本库不代注册；需要时上游自行注册：

    ```java
    // druid 由 database 模块传递引入，StatViewServlet 可直接使用
    @Bean
    public ServletRegistrationBean<StatViewServlet> statViewServlet() {
        ServletRegistrationBean<StatViewServlet> registration =
                new ServletRegistrationBean<>(new StatViewServlet(), "/druid/*");
        registration.addInitParameter("loginUsername", "admin");     // 监控页登录账号
        registration.addInitParameter("loginPassword", "admin123");  // 生产请改强口令
        registration.addInitParameter("allow", "127.0.0.1");         // IP 白名单，多值逗号分隔
        return registration;
    }
    ```

    监控页务必配置登录口令与 IP 白名单，或仅在 LOCAL 模式下注册；同时 SQL 监控需配合 `spring.datasource.druid.filters` 含 `stat` 才有数据；
- **Flyway 版本**随 Boot 3.5.6 BOM（11.7.2；MySQL 支持位于 `flyway-mysql`，本库已随模块引入），遇兼容问题上游可自行覆盖；
- 上游自定义 `DataSource` Bean 可整体接管 zone 数据源装配。

## 9. zone-middleware-security

接口鉴权二方包：**接口签名鉴权**（web / 客户端双策略，自研 MD5 签名，不引入 JWT/saToken 等开源组件）与**用户登录令牌**（不透明令牌 + Redis 有状态会话）；`@ZoneSignCheck` 支持按端点覆盖请求时间窗与声明强制登录（见 9.5）。

### 9.1 签名协议（调用方与服务端共同遵守）

请求须携带的顶层参数（POST 为 JSON body 顶层键值，GET 为 query 参数；同名时 body 优先）：

| 参数 | 说明 |
|---|---|
| `reqId` | 请求唯一标识，32 位字母数字随机串（无连接符），可用 `ZoneSignUtils.generateReqId()` 生成 |
| `timestamp` | 请求时间戳（Epoch 毫秒），与服务端偏差不得超过时间窗（默认 ±5 分钟） |
| `platform` | `web`（web 策略）/ `pc`、`mobile`、`pad`（客户端策略，须携带合法 `deviceId`） |
| `deviceId` | 客户端策略必填，仅允许字母数字下划线连字符；web 策略不需要 |
| 业务参数 | 任意顶层键值 |

签名计算（双端同一实现 `ZoneSignUtils`）：

1. 剔除值为 null 或空串的参数；嵌套对象/数组以 fastjson2 序列化 JSON 串作为值（构建 Map 请用 `LinkedHashMap`/`JSONObject`/POJO，**禁用 HashMap**——无序导致双端拼串不一致）；
2. 按参数名升序排列，`k1=v1&k2=v2` 连接；
3. 末尾追加 `&key=<secret>`；
4. 取 MD5 的 32 位小写十六进制，放入请求头 **`Zone-Access-Token`**。

登录令牌经请求头 **`Zone-Auth-Token`** 携带（`ZoneAuthTokenResolver` 取值）。`BaseRequest.sign` 字段已废弃（仅为存量序列化兼容），服务端只认请求头。

### 9.2 配置项

| 键 | 默认 | 说明 |
|---|---|---|
| `zone.middleware.security.sign.enabled` | `true` | 签名校验开关；纯令牌场景可设 `false`（不装配拦截器与过滤器） |
| `zone.middleware.security.sign.secret` | — | 双端约定签名密钥（web 与客户端共用）；启用签名校验时**必配**，缺失启动即失败 |
| `zone.middleware.security.sign.timestamp-window` | `5m` | 防重放时间窗（全局默认值），同时是 reqId nonce 的存储 TTL；可被注解 `timestampWindowMillis` 属性按端点覆盖（见 9.5） |
| `zone.middleware.security.token.ttl` | `7d` | 登录令牌生存期 |
| `zone.middleware.security.token.renew-sliding` | `true` | 滑动续期：校验通过时生存期重置为完整 TTL |
| `zone.middleware.security.token.multi-device` | `true` | 多端并存；`false` 时单端互斥（新登录撤销该用户全部旧令牌） |

`application.yml` 示例：

```yaml
zone:
  middleware:
    security:
      sign:
        enabled: true
        secret: your-sign-secret   # 启用签名校验时必配
        timestamp-window: 5m
      token:
        ttl: 7d
        renew-sliding: true
        multi-device: true
```

### 9.3 服务端用法

请求 DTO 继承 `BaseRequest`，端点标注 `@ZoneSignCheck`（类/方法皆可，方法优先）；未标注的端点完全不受拦截：

```java
@RestController
public class OrderController {

    @ZoneSignCheck                       // 该端点执行签名校验链
    @PostMapping("/order/create")
    public ZoneResult<String> create(@RequestBody OrderCreateRequest request) {
        // 通过校验链后才会进入；校验失败统一 HTTP 401 + ZoneResult(success=false, code=BIZ-4002, message=鉴权失败)
        return ZoneResult.ok(request.getOrderNo());
    }
}
```

校验链（fail-closed，任一环节失败即 401）：本端点有效时间窗确定（注解覆盖或继承全局，配置非法则该端点全部拒绝）→ 请求头签名 → reqId 非空 → timestamp 时间窗 → platform 分流与 deviceId 校验 → 签名比对（常量时间）→ 登录态校验（仅 `requireLogin = true`，见 9.5）→ reqId nonce 防重放（Redis SETNX，TTL=有效时间窗；**存储不可达时拒绝而非放行**）。POST 仅支持 `application/json`（body 上限 1MB）。

登录态解析（API 方式，适合未声明强制登录的端点；注解声明式校验见 9.5）：

```java
String token = ZoneAuthTokenResolver.resolve(request);          // 无令牌返回 null
SessionUser user = tokenService.parseToken(token, SessionUser.class);
if (user == null) {
    throw new ZoneBusinessException(BusinessError.UNAUTHORIZED); // 未登录/已过期
}
```

### 9.4 登录令牌用法

```java
@Autowired ZoneTokenService tokenService;

// 签发（登录成功后）：返回不透明令牌，交由客户端保存并经 Zone-Auth-Token 携带
String token = tokenService.issueToken("u-1001", new SessionUser("u-1001", "张三"));

// 解析（每次请求）：默认滑动续期；非法/过期/已撤销返回 null 不抛异常
SessionUser user = tokenService.parseToken(token, SessionUser.class);

// 解析为用户信息原始 JSON 串（无需感知业务类型时，语义同上；见 9.5 上下文构建即基于此方法）
String rawJson = tokenService.parseTokenRaw(token);

// 登出：撤销单枚令牌
tokenService.revokeToken(token);

// 踢下线：撤销该用户全部令牌（改密/封禁场景）
tokenService.revokeUserTokens("u-1001");
```

令牌为加密安全随机数（43 位字母数字），服务端 Redis 存 `token → 用户信息` 映射（`zone:security:token:*`），可即时撤销。

### 9.5 注解属性：请求时间窗与强制登录

`@ZoneSignCheck` 提供两个带缺省值的属性（缺省形态下端点行为与纯签名校验完全一致）；方法级声明优先于类级，并支持以本注解为元注解的组合注解：

| 属性 | 默认 | 说明 |
|---|---|---|
| `timestampWindowMillis` | `0` | 本端点请求时间窗（**毫秒**，与 `timestamp` 字段同为 Epoch 毫秒精度），覆盖全局 `timestamp-window`（如 60 秒为 `60000`）；reqId nonce TTL 跟随本端点有效时间窗；**负值属配置错误——该端点 fail-closed 全部拒绝**并记录服务端错误日志 |
| `requireLogin` | `false` | 强制登录：签名比对通过后、防重放校验前，校验请求头 `Zone-Auth-Token` 登录态；缺失/无效/过期统一 401（响应与签名失败一致，不区分环节）；通过后写入登录上下文供业务取用 |

```java
// 敏感端点：窗口收紧到 60 秒并强制登录
@ZoneSignCheck(timestampWindowMillis = 60_000, requireLogin = true)
@PostMapping("/pay")
public ZoneResult<String> pay(@RequestBody PayRequest request) {
    // 通过校验链（含登录态）后才会进入
    ...
}
```

强制登录校验通过后，业务代码经 `ZoneSecurityContext` 静态门面取用登录用户信息（service 层随处可用，无需传递 `HttpServletRequest`）：

```java
String userId = ZoneSecurityContext.currentUserId();                     // 用户信息 JSON 的 userId 字段
String token = ZoneSecurityContext.currentToken();                       // 登录令牌串
SessionUser user = ZoneSecurityContext.currentUser(SessionUser.class);   // 按业务类型惰性解析
```

登录签发沿用 9.4 的 `issueToken`（用户信息 JSON **建议包含 `userId` 字段**——上下文的 userId 即取自该字段，缺失不阻断、仅透传 null）：

```java
String token = tokenService.issueToken("u-1001", new SessionUser("u-1001", "张三"));
```

注意事项：

- `requireLogin` 校验通过即完成令牌滑动续期（与 API 解析路径 `parseToken` 一致）；
- 登录态校验失败发生在 nonce 消费之前，无效令牌请求不占用合法 reqId；
- `ZoneSecurityContext` 依赖 Spring `RequestContextHolder`：非 Web 请求线程（异步 Servlet、自建线程池）中返回 null，此类场景请经 `ZoneAuthTokenResolver` + `ZoneTokenService` 自行解析；
- 未声明强制登录的端点不写登录上下文，门面各方法返回 null 不抛异常。

## 13. 注意事项与常见问题

1. **启动即抛 `SYS-1001 CONFIG_ERROR：spring.datasource.url 未配置`** → 引入 database 模块就必须配置 `spring.datasource.url`。
2. **依赖 `zone-middleware` 坐标后只有 common 生效** → 它是构建聚合父 POM，不是接入坐标；套件引入请用 `zone-middleware-suite`（第 3.2 节）。
3. **依赖 `zone-middleware-suite` 报 `Could not find artifact com.zone.middleware:zone-middleware-suite:jar:...`** → suite 是 `packaging=pom` 的聚合坐标，依赖声明必须加 `<type>pom</type>`（第 3.2 节）。
4. **启动期抛 `IllegalStateException：zone.middleware.security.sign.secret 未配置`** → security 模块 `sign.enabled` 默认 `true`，启用签名校验必须配 `zone.middleware.security.sign.secret`；不需要签名校验时显式设为 `false`（第 9 节）。
5. **Redis 连的还是默认地址（127.0.0.1:6379 db0）** → 检查连接配置是否写成了旧的 `zone.middleware.redis.*` 键——本库已去方言化，只认官方键 `spring.data.redis.*`（第 14 节对照表）。
6. **启动报 `无效的 spring.datasource.type`** → `spring.datasource.type` 只接受缺省（HikariCP）或 Druid 全限定类名 `com.alibaba.druid.pool.DruidDataSource`。
7. **日志 format 非法启动失败** → `zone.middleware.log.format` 只接受 `TEXT`/`JSON`。
8. **yml 与 properties 混写导致配置不生效** → 同一配置项不要在两种文件里重复定义（Spring Boot 中 properties 优先级高于 yml，容易盖掉 yml 值）。
9. **异步线程日志没有 traceId** → MDC 线程级隔离，提交任务前需显式复制 `ZoneTraceContext` 双标识，任务结束 `clear()`。
10. **依赖树出现 jackson** → 本库全模块无 jackson 构件；请排查上游其他依赖，勿往本库模块混入 jackson。
11. **Flyway 对已有数据的库迁移失败** → 开启 `spring.flyway.baseline-on-migrate=true`。
12. **Spring Boot 2.7 下不生效** → 本库基于 Boot 3（jakarta 命名空间 + `AutoConfiguration.imports` 注册），不向下兼容 2.7；上游请升级至 Boot 3.1+。
13. **共享中间件隔离** → MySQL 用独立 database、Redis 用独立 db index，禁止二方库或上游另起实例占端口。
14. **历史沿革** → 本项目前身为 shoan-platform-support，2026-11-15 更名 zone-middleware-support（Maven 坐标与包前缀已同步变更），升级注意替换旧坐标。

## 14. 附录：zone 键 → 官方键迁移对照（历史版本升级用）

2026-11-21 起 redis/database 配置面去方言化：连接、池参数与迁移控制改用 Spring Boot 官方键（超时/池参数未配置时自动取 mode 预设）。从旧版本升级时按下表替换；**保留**的 zone 键仅为行为键。

### 14.1 database（zone.middleware.db.* → 官方键）

| `zone.middleware.db.pool-type: HIKARI\|DRUID` | `spring.datasource.type`（缺省 HikariCP；Druid 填 `com.alibaba.druid.pool.DruidDataSource`） |
| `zone.middleware.db.hikari.*` | `spring.datasource.hikari.*` |
| `zone.middleware.db.druid.initial-size` / `min-idle` / `max-active` / `max-wait` / `keep-alive` / `filters` | `spring.datasource.druid.*`（同名子键） |
| `zone.middleware.db.flyway.enabled` / `locations` / `baseline-on-migrate` | `spring.flyway.enabled` / `locations` / `baseline-on-migrate` |
| `zone.middleware.db.mode` | **保留**（部署模式预设） |
| `zone.middleware.db.mybatis.pagination-enabled` / `mapper-package` | **保留**（本库行为键，官方 MP starter 无此能力） |

### 14.2 redis（zone.middleware.redis.* → 官方键）

| 旧 zone 键（已删除） | 官方替代键 |
|---|---|
| `zone.middleware.redis.host` / `port` / `password` / `database` / `ssl` | `spring.data.redis.host` / `port` / `password` / `database` / `ssl.enabled`（旧 `ssl` 布尔键在 Boot 3.1+ 已是对象键） |
| `zone.middleware.redis.connect-timeout` | `spring.data.redis.connect-timeout` |
| `zone.middleware.redis.command-timeout` | `spring.data.redis.timeout` |
| `zone.middleware.redis.pool.max-active` / `max-idle` / `min-idle` / `max-wait` | `spring.data.redis.lettuce.pool.max-active` / `max-idle` / `min-idle` / `max-wait` |
| `zone.middleware.redis.keep-alive` | 无官方键——本模块按 `zone.middleware.redis.mode` 自动应用（LOCAL 关 / CLOUD 开），不可单独配置 |
| `zone.middleware.redis.mode` | **保留**（部署模式预设） |

### 14.3 迁移自查命令

消费方项目（如 zone-boot-template）升级二方包后执行，确认无旧连接键残留：

```bash
grep -rn --include="*.yml" --include="*.properties" \
  -E "zone\.middleware\.(db\.(url|username|password|driver|pool-type|hikari|druid|flyway)|redis\.(host|port|password|database|ssl|connect-timeout|command-timeout|keep-alive|pool))" \
  src/main/resources/
```

无输出即迁移完整；`zone.middleware.db.mode` / `zone.middleware.db.mybatis.*` / `zone.middleware.redis.mode` 应保留。
